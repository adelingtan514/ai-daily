🎯 今日话题

智能体从「能干活」走向「被授权」

事实
  • Anthropic 让 Claude Approvals 在 PR 上代发审批意见，但最终合入仍归 GitHub 分支保护规则管——AI 拿到的是「建议权」，不是「决定权」。
  • Klarna 与 Adyen 打通智能体代下单支付，但每笔交易仍需消费者确认；支付与电信巨头对智能体代下单态度明显分化。
  • Google Cloud 在 Envoy 代理层加入按 Token 限流、工具路由与安全检查，把预算和权限治理下沉到网络基础设施。
  • AWS Strands Decider v2 用小决策模型替代通用大模型做高频判断，内部工单场景成本降 98%、速度提 78%，说明「分层」比「更大」更省钱。
观点

今天这几条新闻放在一起看，指向同一个转折：智能体的瓶颈已经从「能力」转移到「授权与问责」。模型已经能写代码、下订单、做审批，但行业不约而同地在它前面加了一道道闸门——审批仍由分支保护规则终裁、每笔支付仍需消费者点头、流量在代理层被限流与审计。同时 AWS 的 98% 降本案例提醒我们：真正落地的架构不是让一个更大的模型干所有事，而是大模型负责推理、小模型负责高频判断、基础设施负责治理。对企业的现实含义是：与其纠结选哪个最强的模型，不如先设计清楚「谁授权、谁审计、谁兜底」，这三件事决定了智能体能不能进生产环境。

智能体拿到的从来不是「决定权」，而是「在护栏内行动的权利」。
打工人视角
1

给自己的 AI 工作流加一道「人工闸门」：让 AI 出建议稿，关键节点（发布、付款、对外发送）保留人确认，别让效率吞掉判断。

2

高频、格式固定的判断不妨试试小模型或规则打分，把大模型留给定性推理——参考 AWS 案例，分层往往比升级模型更省钱。

3

把 AI 输出当「草稿」而非「答案」：核验数据来源、检查适用边界，正如《光明日报》今日所言，让工具「激发思考」而不是「终止思考」。
